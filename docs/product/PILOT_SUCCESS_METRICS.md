# Pilot Success Metrics

## Principio

El piloto debe medir valor operativo, no cantidad de pantallas visitadas.

## Baseline inicial

Antes de iniciar, registrar:

- Tiempo promedio para ubicar estado de un expediente.
- Tiempo promedio para responder a cliente sobre estado.
- Numero de archivos/canales usados por expediente.
- Cantidad de tareas vencidas o sin responsable.
- Frecuencia de reportes manuales a socio.
- Nivel de satisfaccion inicial de socio, abogado, asistente y cliente.

## Metricas cuantitativas

| Metrica | Objetivo piloto |
| --- | --- |
| Tiempo para entender estado de expediente | -40% frente a baseline |
| Tiempo para preparar respuesta al cliente | -30% frente a baseline |
| Expedientes piloto con timeline completo | 100% |
| Documentos con visibilidad cliente validada | 100% |
| Acciones criticas con audit log | 100% |
| Salidas IA revisadas por profesional | 100% |
| Automatizaciones dry run sin error critico | >= 90% |
| Usuarios internos activos semanalmente | >= 75% |
| Cliente puede descargar documento autorizado | 100% |
| Incidentes de fuga cross-tenant | 0 |

## Metricas cualitativas

Preguntar a cada rol:

- Socio: "Tengo mejor visibilidad para decidir prioridades."
- Abogado: "Entiendo mas rapido el estado del expediente."
- Asistente: "Me resulta mas claro que hacer despues."
- Cliente: "Puedo ver estado y documentos sin pedirlos por WhatsApp."

Escala: 1 a 5.

Objetivo: promedio >= 4 en cada rol clave.

## Senales de compra

- El socio pide cargar mas expedientes.
- El abogado quiere usar portal con clientes reales.
- El asistente pide automatizar recordatorios.
- El cliente reduce consultas repetitivas por WhatsApp.
- El estudio pregunta por precio, plan o fecha de go-live.

## Criterios GO

- No hay incidentes criticos de seguridad.
- Al menos 7 de 10 metricas cuantitativas cumplen objetivo.
- Promedio cualitativo >= 4.
- Sponsor socio confirma valor claro.
- Pendientes productivos son aceptables para siguiente fase.

## Criterios ITERATE

- Valor percibido, pero hay bloqueos UX, carga inicial o workflow.
- Metricas mixtas.
- Sponsor sigue interesado.

## Criterios NO GO

- No hay sponsor real.
- El flujo no encaja con operacion del estudio.
- Riesgo de datos no aceptable.
- El estudio exige produccion publica inmediata.
